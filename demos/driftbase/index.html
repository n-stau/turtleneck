Branching

A full copy of production per pull request. No copying.

Branches share storage with their parent and only pay for what changes. Test a migration on real data, then throw the branch away.

  • Copy-on-write. A 500 GB branch costs 0 B until you write to it.
  • Schema diff. See what a migration changes before it reaches main.
  • Reset in one command. Rewind any branch to its parent in under 2 seconds.

Instant APIs

Create a table. Query it over HTTPS.

Every table and view gets a typed REST endpoint and a realtime stream, with row-level security from your Postgres policies. Nothing to deploy.

migrations/003_orders.sqlSQL
create table orders (
  id          bigint generated always as identity primary key,
  customer_id uuid not null,
  total_cents integer not null,
  status      text not null default 'open'
);

create policy own_orders on orders
  using (customer_id = auth.uid());
GET /rest/v1/orders200 OK, 18 ms
$ curl "$DRIFTBASE_URL/rest/v1/orders?status=eq.open&limit=2" \
    -H "Authorization: Bearer $TOKEN"

[
  { "id": 48209, "total_cents": 4200, "status": "open" },
  { "id": 48210, "total_cents": 1850, "status": "open" }
]

CLI

Everything in the dashboard, from your terminal.

One binary, no daemon. Scriptable output with --json on every command, ready for CI.

driftbase branch create
Fork any branch, or a point in time up to 7 days back.
driftbase migrate
Apply SQL migrations to a branch, with a dry run.
driftbase dev
Local proxy to your branch, with auto-reconnect.
driftbase logs --follow
Tail queries, errors and compute events.
.github/workflows/preview.ymlCI
# one database per pull request
- run: driftbase branch create pr-${{ github.event.number }} --from main
- run: driftbase migrate --branch pr-${{ github.event.number }}
  Applying 003_orders.sql ... done
  Applying 004_indexes.sql ... done
- run: npm test
- if: always()
  run: driftbase branch delete pr-${{ github.event.number }}
